=====================================================================
FR_CUSTOM KEYBOARD LAYOUT — INSTALLATION INSTRUCTIONS (v1.2.0)
=====================================================================
Author: gatchez
Part of: KeyboardForge (see ../README.md for the full project)

NOTE: `fr_custom` and `rules` in this directory are GENERATED files. Their
source of truth is ../layouts/fr_custom.json. To modify this layout, edit
that JSON file (or use the KeyboardForge CLI/GUI) and regenerate with:

    python3 ../tools/generate_layout.py ../layouts/fr_custom.json .

Do not hand-edit `fr_custom` or `rules` directly -- those edits will be
lost the next time the layout is regenerated.

This folder contains the framework to install a generated XKB layout
system-wide across supported Linux distributions. Direct installer use
defaults to the bundled `fr_custom`/`custom` layout.

FILES INCLUDED:
----------------
1. fr_custom & rules
   - Layout definition (XKB symbols) and XML injection rules.
2. install.sh & uninstall.sh
   - The main entry points. Execute these to manage the layout.
3. modules/
   - Contains the core engine (common.sh), OS configurations
     (debian.sh, fedora.sh, arch.sh), and Desktop Environment setups
     (gnome.sh, kde.sh, xfce.sh).
4. test.sh
   - CI/CD validation script (bash syntax + XML integrity + file checks).
5. VERSION
   - Centralized version tracking.
6. packaging/
   - Templates for .deb (deb/control), .rpm (rpm/fr_custom.spec), and
     Arch (pkgbuild/PKGBUILD) packaging.

=====================================================================
BEFORE YOU BEGIN
=====================================================================
1. Ensure you are executing commands from inside this folder.
2. Root privileges (sudo) are strictly required.
3. Supported Systems:
   - Debian/Ubuntu systems detected by /etc/debian_version
   - Fedora systems detected by /etc/fedora-release
   - Arch systems detected by /etc/arch-release

   Other distributions, including derivatives that do not provide the
   expected marker file, are not automatically detected; use the manual
   installation steps for those systems.

=====================================================================
STEP 1 — MAKE SCRIPTS EXECUTABLE
=====================================================================
Open a terminal in this directory and run:
    chmod +x install.sh uninstall.sh test.sh modules/*.sh

=====================================================================
STEP 2 — RUN THE INSTALLER
=====================================================================
To install interactively, run:
    sudo ./install.sh

The script will ask for confirmation before modifying system files.

ADVANCED FLAGS:
  --yes, -y     (Silent mode, bypasses the confirmation prompt)
  --dry-run     (Simulate installation without persistent filesystem,
                 package-manager, log, lock, or cache changes)

Example: sudo ./install.sh --yes

To install a different generated layout, use the selected identifiers:
    sudo ./install.sh --layout-name my_layout --variant international

The symbols file and `rules` file in this directory must already have been
generated for that same layout and variant. The CLI performs generation
and passes these options automatically.

What the script automates:
 1. Checks for an existing target symbols file or rules entry. If one
    exists without the KeyboardForge installed-version marker, installation
    stops rather than overwriting or duplicating it. Older/manual installs
    without that marker must be resolved explicitly before retrying.
 2. Installs missing dependencies automatically (libxml2-utils / libxml2 /
    pacman's libxml2 + xkeyboard-config, depending on distro).
 3. Saves rollback snapshots for the shared `evdev.xml` and affected system
    configuration so a failed install can be reverted safely.
 4. Copies the selected layout's generated symbols file to
    `/usr/share/X11/xkb/symbols/<layout-name>`.
 5. Validates XML structure (using `xmllint`) and registers a marked rules
    block for the selected layout in `evdev.xml`.
 6. Configures system defaults:
      - Debian: sets `XKBLAYOUT` and `XKBVARIANT` to the selected values.
      - Fedora/Arch: passes the selected layout and variant to `localectl`.
 7. Rebuilds system caches safely where relevant (initramfs / dracut /
    mkinitcpio -P).
 8. Detects Wayland vs X11 and attempts desktop configuration:
      - GNOME: gsettings input-source configuration.
      - KDE Plasma: kwriteconfig5/6 layout configuration.
      - XFCE on X11: xfconf-query and setxkbmap configuration.
      - XFCE on Wayland or other/undetected desktops: manual configuration.

If a required installation step fails or the process is interrupted, the
installer uses its transaction snapshots to restore files and settings
changed by that attempt. If the process is terminated before rollback can
run (for example, a power loss), the next installer run detects and rolls
back the incomplete transaction before continuing. Dependencies installed
by the system package manager are not automatically removed during rollback.

`--dry-run` reports planned actions without creating logs, lock files,
backups, transaction snapshots, markers, or cache changes, and it does not
invoke package managers or desktop configuration commands.

Desktop integration is optional. A failure to configure GNOME, KDE, or XFCE
does not undo a successful system-wide installation; the installer reports
this as a partial result and restores any desktop settings changed during
the failed attempt when possible. Unsupported or unavailable desktop
configuration is reported as requiring manual setup.

=====================================================================
STEP 3 — REBOOT
=====================================================================
Once you see "[✔] Installation Complete", run:
    sudo reboot

=====================================================================
UNINSTALL / RESTORE
=====================================================================
If you need to revert the system to its previous state:
    sudo ./uninstall.sh
    sudo reboot

For a non-default layout, pass the same `--layout-name` and `--variant`
values that were used during installation.

This removes only the selected layout's managed rules block, preserving
other entries in the shared `evdev.xml`. It also restores the saved distro
keyboard configuration and removes the selected symbols file.

On a managed reinstall, existing `.bak_fr_custom` backups (and the Debian
marker for a file that was originally absent) are preserved. They continue
to represent the state from before the first install, rather than being
replaced with files already modified by KeyboardForge.
Running the uninstaller again after a successful removal is safe; it reports
that the layout is already uninstalled and performs no further changes.

The installer also saves the pre-install GNOME input-source value or the
KDE/XFCE keyboard configuration file under
`/var/lib/keyboardforge/fr_custom/`.
Uninstall restores that saved desktop state for the user who installed the
layout. If no state snapshot exists (for example, an older installation),
review desktop settings manually; the uninstaller no longer assumes that
the original layout was `us`.
If a desktop session does not immediately reflect restored settings, log
out and back in. GNOME restoration requires an accessible user session bus;
KDE daemon refresh is best-effort. Check the uninstaller output for warnings
and correct the layout manually in desktop keyboard settings if restoration
could not be applied.

=====================================================================
TROUBLESHOOTING & NOTES
=====================================================================
- Wayland Users: GNOME and KDE configuration use their desktop-specific
  settings tools. XFCE on Wayland and other/undetected desktops require
  manual configuration. If the layout does not appear, use your Desktop
  Settings -> Keyboard and add "French (customized by gatchez)" manually.
- Arch Linux: The console (TTY) keymap is left untouched; only the X11
  layout is configured, since custom XKB layouts are an X11/Wayland
  concept, not a Linux console concept.
- Check `logs/install.log` if any errors occur during installation
  (entries are timestamped).
- Run `./test.sh` any time to verify script syntax and file integrity.
